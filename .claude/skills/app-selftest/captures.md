# 앱 안 키 전달 시험과 화면 전·후 캡처

`docs/ci.md`에 있던 "앱 안 키 전달 검증" 절을 옮긴 문서다. 여기의 인자는 모두 디버그 전용이다. 캡처 인자처럼 값을 받는 인자는 한 덩어리(`--이름=값`)로 쓴다. `--db`·`--select`만 값을 띄어 쓴다.

## 키 전달 시험(`--key-routing-selftest`)

### 돌리기 전에

1. `AsyncGuidanceFixtureCapture`로 합성 사본을 만든다. 이 사본에는 정상 WAV와 깨진 WAV가 있다.
2. 같은 작업 폴더의 Swift 빌드·시험을 먼저 끝낸다.
3. `/tmp/djc-gui.lock`을 잡는다. 이 잠금을 잡은 담당자 한 명만 실행한다.
4. 임시 `DJC_HOME`·`DJC_REKORDBOX_DIR`과 `--db <합성 master.db>`를 모두 지정한다.
5. 디버그 앱을 `--key-routing-selftest`로 띄운다. 이 시험은 1단계의 합성 사본만 연다.

설치 앱은 종료하지 않는다. 바꾸지도 않는다.

### 하는 일

- 자가 테스트는 앱을 활성화하지 않는다.
- 먼저 내부 덱 창의 `makeMain()`·`makeKey()`를 호출해 상태를 확인한다.
- 그 뒤 `NSApp.postEvent`로 그 창 번호에 키를 넣는다.
- 확인하는 입력은 아래와 같다.
  - 실제 검색칸의 글자 입력
  - 곡 목록 탐색, 덱 확대
  - 태그 시트 방향키
  - AppKit 부착 시트·모달의 글자 입력
  - 제품 곡 편집 창의 확대
- 소리는 재생하지 않는다. CGEvent, 화면 좌표 클릭, OS 키 입력도 보내지 않는다.
- 시작과 끝에서 앞에 있는 외부 앱 PID를 비교한다. 앱 비활성 상태도 비교한다.

### 결과 읽기

- 내부 키 창을 만들 수 없으면 이벤트를 보내기 전에 종료 코드 2로 멈춘다.
- 종료 코드 2를 통과로 기록하지 않는다. 앱 활성화로 우회하지도 않는다.
- 종료 코드 0과 `[키 전달] 결과: N/N 통과`는 앱 안에서 이벤트가 창에 닿았다는 근거다.
- 물리 키보드, IME 조합, OS 포커스 전환은 따로 확인한다.
- 이 Mac의 비활성 앱에서는 내부 key·main 창을 만들지 못했다. 그래서 포커스별 전달은 미검증으로 남았다.
- 사용자가 포커스를 내줄 때 확인할 항목은 [#186](https://github.com/fotoner/DJCrate/issues/186)에서 관리한다.

### 활성 모드(`--key-routing-mode=active`)

사용자가 입력을 넘겨줄 시간대를 명시적으로 허용한 #186 세션에서만 쓴다. 이때 `--key-routing-selftest --key-routing-mode=active`를 함께 준다. 이 모드는 DEBUG 전용이다.

1. 두 격리 환경 변수와 합성 곡 조건을 확인한다.
2. 시험 창을 앞으로 놓는다.
3. 로그에 창 제목을 적는다.
4. 사용자의 시험 창 직접 클릭을 최대 10분 기다린다. 실제 활성·키·주 창 상태도 함께 기다린다.
5. 키를 보내기 전에 조건을 확인한다. 조건은 `active=true`, 덱의 `key=true`·`main=true`, 앞 앱이 시험 앱인 것이다.
6. 조건이 맞지 않으면 키 이벤트를 보내기 전에 종료 코드 2로 멈춘다.
7. 키마다 보내기 직전에 대상 키 창과 앞 앱을 다시 확인한다. 입력 대상이 바뀌면 종료 코드 2로 중단한다.

- 4단계에서 기다리는 동안에는 키를 보내지 않는다. 앱을 활성화하지도 않는다.
- 모드 인자가 없으면 기존 비활성 검사를 쓴다. 외부 앱 포커스 보존 assertion도 그대로 쓴다.
- 모드 값 오류, 중복 인자, 빈 격리 환경은 거부한다.
- 활성 모드도 키를 `NSApp.postEvent`로 시험 앱 안에만 넣는다. 소리도 재생하지 않는다.
- 이 결과는 앱 안 전달만 확인한다. 대상은 실제 검색칸, 목록, 태그 시트, 부착 시트, 모달, 곡 편집 창이다.
- 이 결과는 컴퓨터 사용 도구의 실제 키 입력을 대신하지 않는다. 물리 키보드·IME 확인도 대신하지 않는다.
- 아래 키도 확인한다.
  - 목록: Return, Esc
  - 태그: 글자 입력, Return, Esc
  - 부착 시트·모달: Return, Esc
- `DJC_HOME/key-routing-captures`에 대상 창의 전후 JPEG 32개를 기록한다. 확인 창이 닫힌 뒤에는 같은 앱의 주 창을 캡처한다.
- 캡처 실패도 최종 결과에 넣는다.
- 정상 합성 곡에는 DAT·EXT 그리드 분석이 있다. 그래서 편집 창을 열 수 있다.
- 보기 전환은 `AppStorage`의 태그 보기 키만 직접 바꾼다. 이 키는 자가 테스트의 설정 저장 제한과 별개다.
- 제품 설정 정책과 키 전달 정책은 바꾸지 않는다.

### 설정 보관·복원

1. 실행 전에 `defaults export DJCrate <임시 plist>`로 설정을 보관한다.
2. 종료 뒤에는 실행 전후 값이 다른 키만 원래 값으로 되돌린다.

- 실패와 종료 코드 2에서도 복원한다. 자가 테스트가 태그 시트 모드를 바꾸기 때문이다. AppKit도 창 크기를 자동 저장한다.
- 전체 UserDefaults 영역을 가져와 덮지 않는다.

## 화면 전·후 캡처

### 기본 화면

- 화면 비교는 같은 합성 사본에서 `--async-guidance-capture=<임시 폴더>`로 한다.
- 띄운 PID의 창 번호만 `screencapture -x -o -t jpg -l <창 번호>`로 기록한다.

### 메뉴가 보이는 화면(#237 전·후)

- 인자는 `--issue237-capture=<임시 폴더> --issue237-usb-mount=<합성 디스크 이미지 마운트>`다.
- 읽는 것은 아래 둘뿐이다.
  - `LayoutFixtureCapture` 합성 사본. `--db`·`DJC_REKORDBOX_DIR`로 준다.
  - `UsbSelfTestLibrary`로 내보낸 `DJCDEMO` 이미지. `djc lab usb-image`·`usb-export`로 만든다.
- USB 절은 그 볼륨 하나로 바꾼다.
- 창은 `screencapture -l <창 번호>`로 찍는다.
- 메뉴는 앱 안에서 `NSMenu.popUpContextMenu`로 열어 둔다. 그 메뉴 창만 찍는다.
- 비활성 앱은 메뉴를 열지 못한다. 그래서 메뉴가 열려 있는 동안만 잠깐 활성화한다.
- 이때 창은 보고 있는 데스크톱으로 옮겨 다른 창 뒤에 둔다.
- 앱을 쓰는 중에는 돌리지 않는다.

### 곡 목록 칸 배치·머리글(#241·#256 전·후)

- 인자는 `--column-header-capture=<임시 폴더> --column-header-usb-mount=<합성 디스크 이미지 마운트>`다.
- `UsbColumnsFixtureCapture`의 합성 사본(`local`)을 `--db`·`DJC_REKORDBOX_DIR`로 연다. 사본은 `DJC_USB_COLUMNS_FIXTURE=<임시 폴더>`로 만든다. 이 사본에는 앨범아트, 미리 보기 파형, 평점, 곡 색이 있다.
- 그 사본을 한 번 더 복사해 `usb-export --playlist 1`로 디스크 이미지에 내보낸다. 그 볼륨 하나만 USB 절로 읽는다.
- 캡처의 사용자 배치는 미리 보기 칸을 켠 배치다. 앞쪽 칸 순서도 정해 둔다.
- 로컬 → USB 컬렉션 → USB 재생 목록 → USB 쓰기 대기 → USB 목록 → 로컬로 오간다.
- 오가는 동안 창만 `screencapture -l`로 찍는다. 칸 순서와 머리글 자리를 출력한다.
- `[칸 비교]` 줄은 USB 목록이 컬렉션과 같은 칸·순서·폭인지 보인다. 로그는 `grep -a`로 읽는다.
- 디버그 앱은 칸 배치를 환경설정 영역 `DJCrate`에 자동 저장한다. 실행 전에 그 영역을 보관한다. 끝난 뒤 바뀐 키만 되돌린다("설정 보관·복원").
