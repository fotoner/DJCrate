# 다국어(i18n)

앱 화면과 CLI(`djc`)의 문구는 macOS 언어 설정에 따라 한국어·영어·일본어로 나온다.

## 원칙

- 코드에 쓰는 **한국어** 원문이 곧 String Catalog 키가 된다. 영어(`en`)와 일본어(`ja`) 번역은 카탈로그에 둔다.
- `CFBundleDevelopmentRegion`이 `en`이므로 지원 목록 밖의 언어를 쓰는 사용자에게는 **영어**가 나온다(예: 프랑스어).
- 영어 번역이 빠지면 그 문구는 한국어 원문 그대로 보이므로 **en 누락은 늘 0**으로 둔다. ja 누락도 0으로 둔다.
- 카탈로그 원본은 한 곳에 모은다. 화면 문구는 `Sources/DJCrate/Resources/Localizable.xcstrings`에 둔다. 권한 안내와 저작권 줄은 같은 폴더의 `InfoPlist.xcstrings`에 ko·en·ja 모두 둔다.
- CLI의 `Sources/djc/Resources/Localizable.xcstrings`는 앱의 같은 원본을 가리키는 상대 링크다.
- 언어 목록은 `Sources/DJCrate/Info.plist` 한 곳에 둔다. 디버그 실행 파일에는 링커가 `Package.swift`의 `-sectcreate` 설정으로 이 파일을 넣는다. 앱 번들에는 `scripts/build-app.sh`가 번들 Info.plist로 같은 값을 복사한다.
- 실행 파일에 언어 목록이 없으면 메인 번들 언어가 영어뿐이라 카탈로그도 늘 영어를 고른다.

## 언어 고르기

- 핵심부의 `UIStrings`는 카탈로그(`UIStrings.Catalog`)와 `locale`만 든다. 번들은 고르지 않는다. 기본값은 카탈로그 없음과 원문 언어(ko)다.
- 앱은 시작할 때 `UIStrings.useAppCatalog()`(`App/AppStrings.swift`)로 앱 카탈로그 번들과 시스템 언어를 정한다. 키를 준 문구가 찾을 `UIStrings.bundle`도 앱 쪽에 있다.
- CLI는 `CLILocalization.configure(lab:)`에서 `Locale.preferredLanguages`와 `DJC_LANG`으로 언어를 고른다. 그 뒤 그 언어의 리소스 번들과 로캘을 정한다. 실험 명령 `djc lab`은 카탈로그 없이 원문으로 낸다. 수 형식만 시스템 언어를 따른다.
- CLI에서는 `DJC_LANG=ko|en|ja`가 시스템 설정보다 우선한다. `DJC_LANG`이 비어 있으면 시스템 설정을 따른다.
- 두 값 모두 지역 접미사가 붙은 이름도 받는다(예: `en-US`, `ja_JP`). 고른 값이 지원하지 않는 언어면 영어로 낸다.
- CLI의 JSON 출력에서는 오류 `message`만 번역한다.
- 단위 시험은 카탈로그를 정하지 않는다. 그래서 원문과 원문 언어(ko)를 쓴다. 시스템 언어와 관계없이 한국어 문구로 비교할 수 있다.

## 코드에서 쓰는 법

| 쓰는 곳 | 쓰는 법 |
|---|---|
| 문자열이 필요한 곳(NSAlert·토스트·오류 이유·계산한 표시 이름·AppKit 제목) | `String(ui: "곡 \(count)개를 지웠습니다")` |
| SwiftUI 제목 인자(`Text`·`Button`·`Label`·`Toggle`·`Picker`·`Section`·`Menu`·`.help`·`.accessibilityLabel`·`Hint`·`Value`·`Window`) | `Text(.ui("재생"))`, `Button(.ui("쓰기…")) { … }`, `.help(.ui("…"))` |
| 번역하지 않는 글(곡 제목·숫자·기호·브랜드 이름 `rekordbox`·`DJCrate`·`BPM`) | `Text(verbatim: "…")`, 또는 `String` 값을 넘긴다 |

- 앱과 CLI, 하위 모듈은 모두 `DJCDomain`의 `UIStrings`에 있는 `String(ui:)`·`.ui(…)`를 쓴다.
- SwiftUI에 문자열 리터럴을 그대로 주지 않는다(예: `Text("…")`). 리터럴은 메인 번들에서 찾으므로 개발 빌드와 앱 번들이 다르게 보인다.
- 검사(`scripts/i18n.swift check`)가 `String(ui:)`·`.ui(…)` 밖의 지역화 문구를 막는다.

### 하위 모듈의 문구

하위 모듈은 `DJCDomain`처럼 앱·CLI 밖에 있는 모듈이다. 전체 목록은 [도구](#도구) 절의 표에 있다.

앱 화면에 닿는 하위 모듈 문구도 `String(ui:)`로 써서 키를 앱 카탈로그에 모은다. 쓰기 막힘 이유, 편집 거절 이유, 확인 창(`ReflectionPrompts`)이 그 예다. `DJCError.errorDescription`과 `recoverySuggestion`, 단축키 이름 등도 그렇다.

하위 모듈은 자기 번들(`Bundle.module`)을 두지 않는다. PATH에 복사한 `djc`처럼 번들이 없는 곳에서 `Bundle.module`이 멈추기 때문이다.

CLI를 복사할 때는 `DJCrate_djc.bundle`도 실행 파일 옆에 둔다. 이 번들이 빠졌으면 CLI는 한국어 원문으로 실행한다.

### 번역하지 않는 글

아래 글은 번역하지 않는다.

- 개발자용 `djc lab …` 출력
- 표준 오류 로그(예: `[앱 오류] …`)
- 앱 자가 테스트·성능 기록 출력(`Diagnostics/`): 문서가 그 한국어 줄을 grep한다
- rekordbox나 파일 형식에 쓰는 문자열
- 파일·폴더 이름(예: `DJCrate 편집본`)
- 코멘트 규칙의 한국어 토큰

### 같은 원문, 다른 뜻

같은 한국어라도 뜻에 따라 번역이 달라야 하면 그 문구에만 키를 따로 준다. 재생 버튼의 "재생"과 재생 횟수 칸의 "재생"이 그 예다.

- String: `String(localized: "library.column.plays", defaultValue: "재생", bundle: UIStrings.bundle)`
- SwiftUI: `LocalizedStringResource("…", defaultValue: "…", bundle: UIStrings.bundle)`
- 키는 `영역.뜻` 꼴의 영어 점 표기로 짓는다.
- 검사는 `bundle: UIStrings.bundle`이 있을 때만 이 형태를 받는다.

### 보간과 자리표시자

- 어순이 언어마다 다르므로 문장 조각을 `+`로 잇지 않는다.
- 문장 하나를 키 하나로 두어 바뀌는 값만 보간한다(예: `"\(name)을 지웠습니다"`).
- 보간 값이 둘 이상이면 번역에서 순서를 바꿀 수 있게 `%1$@`·`%2$@`처럼 위치를 적는다.
- 키의 자리표시자는 보간 타입이 정한다: 문자열 `%@`, 정수 `%lld`, `Double` `%lf`.
- `Double`을 그냥 넣으면 소수 여섯 자리가 나오므로 `\(bpm, format: .number.precision(.fractionLength(2)))`나 `specifier: "%.1f"`로 형식을 준다.
- 번역 값 안의 글자 `%`는 `%%`로 쓴다.
- 영어에서 수에 따라 달라지는 말은 카탈로그의 복수형 변형(`one`·`other`)으로 둔다. 일본어와 한국어는 변형 없이 하나로 둔다.

### 수와 날짜

화면의 수와 날짜는 로캘 형식으로 쓴다. 아래 표의 뒤 세 줄은 로캘을 따르지 않는 고정 표기다.

| 값 | 쓰는 법 |
|---|---|
| 화면의 소수(BPM·dB·LUFS) | `.formatted(.number.precision(.fractionLength(n)).grouping(.never))` 또는 `specifier:`. 둘 다 로캘 소수점을 따른다 |
| 날짜·시각 | `.formatted(date:time:)` |
| 재생 위치 시계(`m:ss.mmm`) | DJ 기기와 같은 고정 표기 |
| 입력 칸 값(BPM 입력) | 파싱과 짝이므로 그대로 둔다 |
| rekordbox XML·DB·파일 이름에 쓰는 수 | 늘 `String(format:)`(POSIX) |

## 도구

```bash
swift scripts/i18n.swift sync    # 빌드 → 코드에서 뽑은 문구로 카탈로그 고치기(새 문구 더하기, 안 쓰는 문구 빼기·옛 번역 출력). 고정 서식으로 저장
swift scripts/i18n.swift check   # scripts/check.sh(전체, 문구가 바뀐 --changed)가 부른다: 카탈로그 = 코드, en·ja 누락 0, 자리표시자 일치, .ui 밖 문구 0, 고정 서식
swift scripts/i18n.swift format  # 빌드 없이 카탈로그를 고정 서식으로만 다시 쓰기(JSON을 손으로 고친 뒤)
```

- 컴파일러가 타입을 보고 문구를 뽑아 `.stringsdata`에 담는다. `Package.swift`에 `defaultLocalization`이 있으면 모든 타깃에서 문구가 나온다.
- `scripts/i18n.swift`는 디버그 빌드 결과 가운데 `modules`에 든 모듈의 문구만 쓴다.

| 묶음 | `modules`에 든 모듈 |
|---|---|
| 앱·CLI | `DJCrate`, `djc` |
| 하위 모듈 | `DJCDomain`, `RekordboxKit`, `DJCStorage`, `DJCAnalysis`, `DJCApplication`, `DJCAdapters` |
| 빠지는 것(문구 없음) | `DJCEnvironment`, 실행 타깃 |

### 새 문구를 더하는 순서

1. 코드에 한국어 원문을 쓴다.
2. `sync`를 돌려 카탈로그에 새 문구를 더한다.
3. Xcode에서 `.xcstrings`를 열어 en·ja 번역을 채운다. JSON을 직접 고쳐도 된다.
4. 채운 번역의 `state`는 `translated`로 둔다.
5. `check`를 돌려 누락과 서식을 검사한다.

### 고정 서식

카탈로그는 늘 아래 고정 서식으로 저장한다.

| 항목 | 서식 |
|---|---|
| 들여쓰기 | 2칸 |
| 키와 값 | `"키" : 값` |
| 키 순서 | 모든 객체의 키를 UTF-8 바이트 순서로 |
| `/` | 이스케이프하지 않음 |
| 빈 객체 | 줄바꿈 둘 |
| 파일 끝 | 줄바꿈 하나 |

`sync`·`format`이 이 서식으로 저장하므로 바뀐 문구가 없으면 파일이 바이트까지 그대로다. 손으로 고쳐 서식이 어긋나면 `check`가 알리니 `format`을 돌린다.

### 문구를 고칠 때

문구를 고치면 키가 바뀌어 옛 번역이 카탈로그에서 빠진다. `sync`가 뺀 문구의 옛 번역을 출력하니 그 번역을 새 키에 옮겨 고친다.

## 문체

### 영어

- 메뉴·버튼은 "Restore Before Write…"처럼 Title Case로, 설명·안내 문장은 문장형으로 쓴다.
- 늘 대화상자·시트를 여는 항목은 원문과 같게 "…"로 끝낸다. 가끔만 확인 창이 뜨는 항목에는 "…"를 붙이지 않는다.
- "Please"는 쓰지 않는다.
- 막힘·오류 이유는 원문처럼 무엇을 하면 되는지까지 한 문장으로 쓴다.

### 일본어

- 문장은 です・ます체로, 버튼·메뉴는 짧은 명사형·동사형으로 쓴다(예: 「書き込む」「削除」).
- 일본어와 라틴 문자 사이에 빈칸을 두지 않는다(예: `rekordboxに書き込む`).
- 문장 부호는 전각 `、。「」（）`으로, 말줄임표는 원문과 같은 "…"로 쓴다.

### 공통

- rekordbox 표기는 아래 용어표대로 rekordbox 해당 언어판과 같게 쓴다.
- `rekordbox`는 늘 소문자로, 제품 이름 `DJCrate`는 그대로 쓴다.
- 약어 `BPM`·`USB`·`XML`도 번역 없이 그대로 쓴다.
